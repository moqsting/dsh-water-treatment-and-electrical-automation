### P0（阻止继续开发）

### P1（建议近期处理）

1. **补丁仅在本机 checkout，DSH 升级后会丢失**：六轮补丁作用于 `0.2.0-rc.2` 版本目录，DSH 升级/重装后需重放（`.audit-tests` 下 8 个 patch 脚本可重放，重放后重跑 4 套测试验证）。建议：升级 DSH 时先备份、升级后重放补丁、以本报告第 2 项 15 个特征作为验收清单。
2. **补丁未提交上游**：与上游偏差需要长期跟踪；建议整理 diff（4 个文件的原始备份已存）提交 deepseek-harness 上游或维护本地 patch 包。

### P2（可记录后续处理）

1. **integration-pack 内残留目录**（打包分发前清理）：`pyenv`（早期 pip 安装失败产物，受限会话无权限删除，需完整权限手动删除）、`pydeps_dl`（依赖下载缓存，可安全删除）、`reports\`（冒烟测试产物，分发时可清空）。三者不影响功能，只影响包体积与整洁。
2. **真实 GitHub 网络端到端测试**：本机网络策略阻断直连 GitHub，web fetch 的 GitHub 专项测试以本地模拟完成；建议在非受限网络执行一次真实验证（`node .audit-tests\web-fetch-test.mjs` 仅覆盖本地模拟，真实验证需另行编写或手动）。
3. **compare→cost 多供应商行语义**：契约放行但同设备多行会重复计价（文档已提示"先筛选"）；如需硬约束可后续在 cost 入口加重复键检测。

1. EPERM 语义混叠（Windows 底层现实：占用/权限/实时防护同报 EPERM，诊断以"五类并列+验证"呈现，归因靠人工核查——这是纪律本身）；
